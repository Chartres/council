What went wrong tonight, and what each option fixes either way

Your session ran signed out, so its transcript stayed on your phone. These causes come from reading the code and tonight's event log. They are likely causes; none has been reproduced on a phone yet.

  1. Only Franklin. In voice mode one adviser answers per turn, and the model alone picks who. The server does not tell it who spoke last. If the model writes "Benjamin Franklin" instead of the short name, the code does not recognise it and falls back to the first seat. Fix: the server picks the speaker (who has spoken least, or the one you named) and tells the model.
  2. One sentence, a skip, then something else. Sentences are read aloud as they stream in. The finished reply is then checked: unverified quotes are cut, which hits Franklin's sayings. When the checked text no longer matches what was being read, the rest is dropped and the next question is read in another voice. Separately, a sentence that takes over 6 s to fetch is read by the phone's own voice. Fix: read only the checked reply, in order, one voice.
  3. Microphone dropped 4 s after you started. The log shows the phone muted the microphone for over 2 s right after Talk opened. A likely trigger is the silent sound the app plays to unlock audio in that same tap. Fix: open the microphone first, and reopen it once on its own if it comes back.
  4. Slow writing with no status. Firefox on Android has no live dictation, so your words go to the server in parts. While that happens the main status still said "Recording". Fix: the status counts the parts still being written (step 3 above).
  5. Two text boxes. The screen had a reply box, a draft box in the bar, and a note box under each adviser. Every option above keeps one.
